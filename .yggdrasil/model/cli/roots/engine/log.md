## [2026-08-19T15:33:46.510Z]
Role induction lands: a per-partition, bucket-weighted clustering pass groups method and type scopes by a catalog-free feature bag of name tokens, declared supertypes, decorations, and a handful of package imports, then cuts the resulting hierarchy at the point that minimizes a description-length cost rather than at a fixed cluster count, so the number of roles a codebase yields is discovered from its own structure instead of guessed in advance. Classification of every scope against the resulting cluster centers is the same rule build time, live editing, and hook checks will all share, so a scope's role can never be judged differently depending on which of those paths asked. A scope whose best match is barely better than its next-best rival, or whose nearest medoid turns out to be a near-duplicate of another surviving cluster rather than a genuinely different grouping, is marked ambiguous instead of forced into a role it does not clearly belong to — ambiguity here is deliberate silence, not a bug, and a duplicate-cluster artifact of the clustering step is explicitly kept from manufacturing false ambiguity for an otherwise well-established group. Every scope's resolved role is persisted by a stable key so a later pass can recognize a scope it already classified even after a change that would otherwise make the scope look like it no longer belongs anywhere. A role's identity is derived entirely from the content of its own membership, so two runs over identical code produce identical role identities with nothing carried over from a prior run by convention. A file's own role is derived separately, as the plurality role among the methods and types it contains, with ties broken deterministically rather than by insertion order. Finally, a role's usefulness is measured directly: a role whose members do not actually compress better under role-specific expectations than under the wider partition's own expectations is flagged as offering no real signal, so a role invented by the clustering machinery without any underlying substance cannot silently start dictating conventions to the scopes it happened to gather.

## [2026-08-19T20:34:59.513Z]
Several counting and candidate-detection gaps in the acceptance chain were closed. A categorical trait shared by scopes of more than one kind (for example, a naming pattern that applies to both methods and types) previously had its recognized value set overwritten by whichever kind happened to be processed last, silently erasing every value only the other kind used and, with it, every fact that kind could have produced; the two kinds' value sets are now combined instead of one replacing the other. A boolean trait's candidacy for a given kind was previously decided only by whether some scope of that kind was ever observed with the trait present, which meant a trait genuinely applicable to a kind but never actually true there could never even be considered — including the common case where the trait is common on one kind and simply absent on another; candidacy is now decided by whether the trait's own applicability reaches that kind at all, regardless of whether it happens to be true anywhere. A related filter meant to reject an absence claim describing a universally-absent trait was checking only one kind's own population instead of every kind sharing that trait, which could wrongly discard a real, local absence pattern; it now checks the trait's true occurrence across every kind that shares it. A displayed count of exceptions to an accepted pattern was being computed from the wrong population (the subset known to have aged past a freshness window) instead of the trait's full observed population, understating it whenever history information was thin or absent. Two places that build a plain lookup object from mined values are now built through an intermediate map instead of direct property assignment, closing a gap where a mined value that happened to equal a JavaScript object's own reserved property name would silently vanish from the output; the same care was applied to a place that reads a scope's stored value by an externally-supplied name, which could previously read an inherited object property instead of failing safely when the named value was never actually recorded. A per-file module-directory lookup that re-derived its answer independently of the pass that already decided each file's module boundary could, in an edge case, disagree with that decision; it now reads the answer directly from the already-settled result instead of risking a second, possibly different one.
