## [2026-07-31T17:59:32.846Z]
An import specifier resolved fresh from source can name any file on disk, including one this graph excludes — a coverage.excluded root, or a nested project's own boundary. The owner index that turns such a resolved file into a node must answer 'no owner' for an excluded file the same way every other ownership question in this graph already does, or an import reaching into an excluded subtree keeps naming its textual owner and wrongly trips the undeclared-dependency check. The Go and Java package resolvers go one step further: given a package/wildcard import, they pick a representative file for the whole directory by consulting an owner index too, so they can attribute the import to that file's owner. That picking index needs the identical guard, or it can land on the one excluded file in an otherwise ordinary package and silently drop an edge that is legitimately reachable through the package's other, non-excluded files — the opposite failure from leaking an excluded file's own ownership, and just as wrong. Every caller that resolves a specifier fresh from source now builds its owner index through one shared, exclusion-guarded constructor, so the index that decides a resolved file's node and the index that arbitrates a package's representative can never drift apart on what counts as excluded.
## [2026-07-31T23:14:34.795Z]
The shared owner-set decision a split package's import resolution depends on used to weigh every file in the directory toward whether the package looked single-owned or genuinely split, including a file the graph excludes from coverage entirely. That let an adopter's own exclusion list decide, wrongly, whether a package still looked split — the excluded file's owner kept a vote over a directory it no longer has any real files in. The decision is now made only over the files that remain once an excluded one is dropped.
## [2026-07-31T23:14:40.380Z]
Correcting the split-package ownership rule further: dropping an excluded file's own vote was right, but the prior version also dropped every OTHER file belonging to that same excluded file's owner, so a component still mapping several non-excluded files in the same package could lose its whole claim on the package the moment any one of its files was excluded. The rule now keeps every surviving file's vote exactly as it was — an exclusion removes only its own file from consideration, never any other file's owner from the tally. Two or more distinct owners left among the surviving files still means a genuine split and stays silent; one owner left attributes the import to it; nothing left because every file was excluded stays silent because the target itself is gone.
