A wildcard or package-level import resolves to a single representative file for its whole directory, picked by asking which node owns the files in that directory. That pick used to ask about every file in the directory regardless of whether the graph excludes it, so an adopter's own coverage.excluded entry could count toward whether a package looked single-owned or split — the excluded file's owner still had a vote it should never have had. The candidate list a package's ownership decision is drawn from now drops any excluded file first, so the split-or-single-owner call is made only from the files this graph still enforces.
## [2026-07-31T23:14:51.954Z]
The previous fix for a split package's ownership decision went too far the other direction: it discarded an owner's OTHER files entirely once one of that owner's files was excluded, so a component still mapping several files in a package — only one of them excluded — could be dropped from the ownership tally altogether and lose a real, still-enforced dependency. Ownership is now decided over exactly the files that remain after the excluded one is dropped: no more, because the excluded file's own vote is still gone, and no less, because every one of its owner's other files still counts on equal footing with everyone else's.
