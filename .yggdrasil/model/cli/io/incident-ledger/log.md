Owns the committed incident ledger on disk. The ledger is human testimony, not derived state, so it is committed (it must survive across clones and be reviewed in a diff) yet it is never treated as reviewed source. Kept as its own persistence concern rather than folded into the general stores so that its small, self-contained surface stays legible and does not inflate an unrelated node. Entries are append-only and their datetimes are kept in time order; the write goes through the shared single-append chokepoint and the clock is injected by the caller so the store holds no wall-clock of its own. A missing ledger is a valid empty state — a repository that has never recorded an escape simply has no file yet — so reads tolerate absence and the first write lays down a one-time explanatory preamble ahead of the first entry.
## [2026-07-14T09:37:47.702Z]
Extended the committed incident ledger so an entry may optionally carry the rule an escape is attributed to, recorded as a machine-shaped attribution line beneath the header ahead of the human prose. Backward compatibility is a hard constraint: the ledger is committed, long-lived testimony, so an entry written before attribution existed carries no such line and must still parse exactly as before, and the optional line is never a header so it cannot affect the strictly-ascending-datetime integrity signal. Added a per-rule tally that counts only miscalibration reports which name a rule, deliberately excluding unattributed ones — those remain in the repository-wide count but are not evidence against any single rule — so the rule-health view can attribute recorded misses to the specific rule responsible without over-claiming.
## [2026-07-14T09:56:41.643Z]
Moved per-rule attribution from a metadata line in the entry body onto the header line as a trailing token, because a body-scanning reader let a free-text reason forge an attribution: an incident recorded without naming a rule, whose prose happened to contain a line reading like an attribution, was silently read as attributed to that rule and surfaced against it in the rule-health view. Attribution now rides only the machine-written header, which is validated at write time, so the human's prose can never be mistaken for it. An unattributed entry's header is byte-identical to the original form, so older entries and every entry recorded without attribution keep parsing unchanged, and the datetime capture is untouched so the ascending-order integrity signal is unaffected. The reader no longer inspects the prose body for attribution at all.

## [2026-07-20T04:43:32.420Z]
The incident ledger is the one human-signed record of what slipped past enforcement, and every entry must remain machine-parseable. When the existing ledger file did not end in a newline — as can happen after a hand edit — appending a new entry glued its header directly onto the trailing line, so that entry stopped parsing and was silently lost. Appending now inserts a separating newline whenever the file does not already end in one, testing for an actual trailing newline rather than treating trailing whitespace as sufficient, so a new entry always begins on its own line.
