## [2026-07-13T22:29:27.328Z]
Added the pure engine that derives, per rule, how often its refusals were later waived or overturned — the false-block signal. A block is a distinct refused (rule, unit) pair on record; a block is FALSE when a live suppress waiver for that same rule now covers the unit, either because it is still refused and a human waived it, or because it later flipped to approved after a waiver changed rather than because the code was genuinely fixed. Requiring the live waiver is the crux: a refused-then-approved flip with no waiver is a real code fix (the rule working), and must never read as a false block. The rate is an empirical-Bayes shrink of false-blocks over blocks computed strictly within the reviewer kind, because deterministic and model-judged rules generate false positives by different mechanisms and must never be pooled together; a small-sample flag rides alongside so the presenter can state the uncertainty in plain words. Everything arrives as plain-data parameters — the telemetry and the live-waiver coverage are resolved at the command boundary — so this engine reads no sidecar and stays out of any verdict path.
## [2026-07-13T23:15:48.644Z]
Narrowed the false-block signal's honesty claim in its documentation to match what the join can actually guarantee. Requiring a live covering waiver excludes the SYSTEMATIC false positive — a genuine code fix (a refusal that later passes with no waiver over it) is never counted. But a residual, coincidence-only over-count remains and is now disclosed: waiver coverage is resolved at file and component granularity, not per line, because a refusal on record carries no line number. So a same-rule waiver sitting on a component alongside an UNRELATED refusal from that same rule can tally the unrelated refusal as a false block. It is coincidence-gated, always carries the small-sample honesty label, and never gates a build, so it is documented rather than engineered away — line-level attribution would require refusals to record their line, a recording change not justified for a read-only signal that never blocks anything.
