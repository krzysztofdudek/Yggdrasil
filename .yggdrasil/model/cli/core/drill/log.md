New falsifiability runner. It discovers a per-rule library of example files whose directory prefix encodes the expected verdict (a "violates" example MUST be refused; a "satisfies" example MUST pass), re-runs the real rule over them, and classifies each as pass, a MISS (a violation the rule failed to catch), a FALSE-ALARM (a clean example the rule wrongly rejected), unrun (could not be evaluated), or unsupported (the rule needs context this mode cannot supply). This exists so a maintainer can confirm a rule still catches what it should after the rule or the surrounding code evolves. The module is kept reproducible and free of both the code-execution layer and the network reviewer by having the command layer inject those two impure operations; everything the module does itself (discovery, hashing, prompt assembly, classification, exit-code logic) is deterministic. It never writes saved verdicts.
