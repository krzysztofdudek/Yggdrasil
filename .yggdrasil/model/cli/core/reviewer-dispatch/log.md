## [2026-08-06T14:23:26.192Z]
Talking to the reviewer is now its own kind of code, held apart from the stage that sequences it. Everything that actually asks a model for a verdict lives here: grouping a run's fillable pairs by resolved tier so a provider is stood up and probed once per tier rather than once per pair, loading subject and reference bytes byte-identically to the verifier, resolving paired files and suppressed line ranges before anything is spent, measuring the assembled prompt against the tier's ceiling, casting the consensus votes, and folding the answer into a content-addressed entry. The rule that a component's code must produce the same result from the same input does not apply to it, and cannot: a model's answer to identical input is not guaranteed identical, so demanding otherwise would forbid the work rather than improve it. What holds instead is that every verdict is stored under a hash of the inputs that produced it and is honored only while those inputs still hash to the recorded value, so reproducibility is proven where the result is kept rather than where it is obtained. Every other rule the surrounding code answers to still applies here, including the mechanical one that this code must take its clock, its randomness, and its environment as inputs handed to it rather than read off the running process. Separating it removes the only reason anyone had to switch a rule off in this area: previously both files carried a marker disabling that rule, which hid the mismatch instead of naming it and left a small unchecked island inside code that is otherwise judged in full.
