## [2026-08-06T14:23:26.192Z]
Talking to the reviewer is now its own kind of code, held apart from the stage that sequences it. Everything that actually asks a model for a verdict lives here: grouping a run's fillable pairs by resolved tier so a provider is stood up and probed once per tier rather than once per pair, loading subject and reference bytes byte-identically to the verifier, resolving paired files and suppressed line ranges before anything is spent, measuring the assembled prompt against the tier's ceiling, casting the consensus votes, and folding the answer into a content-addressed entry. The rule that a component's code must produce the same result from the same input does not apply to it, and cannot: a model's answer to identical input is not guaranteed identical, so demanding otherwise would forbid the work rather than improve it. What holds instead is that every verdict is stored under a hash of the inputs that produced it and is honored only while those inputs still hash to the recorded value, so reproducibility is proven where the result is kept rather than where it is obtained. Every other rule the surrounding code answers to still applies here, including the mechanical one that this code must take its clock, its randomness, and its environment as inputs handed to it rather than read off the running process. Separating it removes the only reason anyone had to switch a rule off in this area: previously both files carried a marker disabling that rule, which hid the mismatch instead of naming it and left a small unchecked island inside code that is otherwise judged in full.
## [2026-08-07T11:02:26.017Z]
The size of the prompt actually sent to the reviewer is now recorded alongside the verdict it produced. It is a record of inputs the verdict hash already covers, never an input of its own, so writing it invalidates nothing and an older lock that lacks it simply keeps being measured the old way. It exists so a later verification can answer the prompt-size question without resolving companions and reassembling the prompt, which was the dominant cost of checking a repository where nothing had changed.
## [2026-09-06T17:57:06.854Z]
The per-pair work of gathering what a judge sees, and computing the identity the resulting verdict is stored under, moved out of this stage into the single module that now owns it. Nothing about the dispatch changed: this stage still decides whether to spend, still gates the assembled size against the tier's ceiling, still fails closed on every disposition that is not a real judgement. What changed is that it no longer holds its own copy of the assembly, so a second kind of judge cannot end up judging something subtly different from what this stage would have sent.
## [2026-09-23T11:59:58.191Z]
The external-judge channel is removed: the reviewer configured in yg-config.yaml, through yg check --approve, is the only judge of a prose rule, by the owner's decision that there is to be no other. The review package assembly now serves the fill alone, and verdicts an earlier release recorded through the channel still re-prove by the same hash, so no adopter's lock is broken.
## [2026-09-23T19:26:20.331Z]
A reviewer that could not run, or failed mid-review, was reported with one generic sentence about an endpoint, network and credentials, whatever the provider was. A missing CLI binary, a missing API key, a refused key, an unknown model and a timeout therefore looked identical, and the adopter could not tell whether to install something, log in, fix the model name or raise the timeout. The availability gate now asks the provider for its own reason and prints it, every infra report ends by naming debug: true and the debug log where the provider full output goes, and the reason is kept on each infra report entry so the closing summary can show it.
