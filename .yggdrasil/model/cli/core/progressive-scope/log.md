Adds three pure graph-traversal helpers that answer "which other graph elements does a starting point reach", with no I/O and no per-node applicability filtering: an unconditional closure over an aspects implies edges, a reverse index from a relation target back to every node that declares a relation to it (any relation kind, not only port consumption), and a flows participant set that also includes each declared participants descendants. They exist because the existing equivalents in the aspect-resolution engine are node-bound and when-filtered by design, answering "what applies to this one node", while a later scope-narrowing stage needs the opposite: a structural, node-free answer to "what does this rule or flow reach everywhere", so that stage can compose the full set of implicated rules without re-deriving graph-shape facts ad hoc or duplicating the per-node cascade.
## [2026-08-12T07:46:51.898Z]
Composes the structural reach helpers into the burn table itself: given the set of files a change touched, the run's expected rule checks, and the observations their stored verdicts recorded, decide exactly which checks that change is accountable for. Each kind of changed input reaches something different, and conflating them either over-gates or silently under-gates. A source file reaches the checks whose review subject contains it, plus the component that owns it, resolved from mapping patterns alone so a deleted path still finds the component that answered for it. A rule's own files reach that rule and everything it implies. A component declaration reaches that component together with its descendants, its ancestors and every component declaring a relation to it, because rule attachment can move in all three directions. A flow reaches its rules on every participant. Writing a component's log entry is deliberately carved out to re-gate only that component's log channel: a log entry on a shallow component changes no rule input, yet the naive reading would re-gate almost the whole graph, and log-only changes are a large share of the commits that touch the model at all. A check with no stored verdict is re-gated rather than assumed inherited, so an environment whose local result cache is empty can never read as fully verified. Architecture changes escalate to gating everything, as do the coverage scope, the schema version and the set of reviewer tier names, because no per-check intersection can bound what those move, while ordinary configuration churn moves no obligation and gates nothing. Every row is an inverted index probed once per changed file rather than a per-file scan over all checks, because at this graph's size the scan shape costs seconds per run.
