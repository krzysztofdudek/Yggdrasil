## [2026-07-20T04:43:31.487Z]
Three protections to keep the fill stage from ever presenting a false green or losing a safety signal.

The fill-and-approve run — the step the workflow treats as the terminal act of a change — must surface the same review-cadence reminders (a rule past its scheduled re-review date) that the plain read-only check surfaces. The approve run now threads the same injected clock through both its cost-preview report and its final report; the clock is injected rather than read from ambient system time so the behavior stays deterministic.

The append-only integrity check refuses whenever a historical entry inside the hashed prefix has been altered. If closure recomputed the baseline from the current altered bytes, it would re-pin the baseline to the tampered content and hide the break from that refusal. Closure now advances the baseline only when the current content is a pure append over the stored one; on detecting tampering it keeps the last known-good baseline so the refusal survives. The source fingerprint still advances normally — only the log baseline is protected.

Garbage collection of stored verdicts must never prune an entry that only looks detached because the current run could not fully compute the graph. Two conditions now block pruning.
