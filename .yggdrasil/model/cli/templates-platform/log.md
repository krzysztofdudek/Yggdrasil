The per-node size guard changed from limiting the raw count of mapped source files to limiting the total number of characters in a node's reviewer context — its mapped source files plus the reference files of its effective aspects — and from a non-blocking warning to a blocking error. The motivation is that the reviewer concatenates all of a node's files into each aspect prompt, so an oversized node risks exceeding the model's context window, which deterministically rejects unchanged code near the truncation point; a file-count limit missed this because one very large file could stay under the count while still blowing the prompt. Binary files do not count toward the budget, and a node mapping a single unsplittable generated or binary artifact (a lockfile, an append-only changelog, an image) may carry a documented per-node exemption with a required justification.

Three corrections to the promise this installer makes about a user's bytes.

The import line it writes into the Claude-specific instructions file is now matched only outside fenced code blocks, as the marker-block surgery already was. The line ending a rewritten file comes back in is now the one the file mostly uses, not whichever one appears at least once. The module's own contract now also states the one caveat honestly: a file with mixed endings is normalized to its majority, so the minority terminators change even though no line's text does.

The sweep that removes an entry an older installer left in an Aider configuration now decides the follow-up key removal within the block that entry actually sat in. The report the installer returns now also lists the artifacts it owns on every run, in the project's own spelling, regardless of whether that run rewrote a byte.
