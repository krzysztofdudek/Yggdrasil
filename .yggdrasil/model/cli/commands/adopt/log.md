A repository does not drift into being governed by an architecture graph; someone decides that it is. Until now the product had no way to make that decision, and no way to record it. A proposed graph was moved into place by hand: nothing checked that it would even load, nothing recorded the verdicts that cost nothing to record, nothing said how much of the code already present the new rules refuse on the first day, and nothing anywhere carried who accepted what. This command is that missing signature.

Three properties are deliberate and each answers a way the hand-moved version went wrong. It is a transaction: either the repository ends with the accepted graph, or it ends exactly as it was, including when the graph turns out not to fit the code it names once it is finally beside it. It never merges: a rule taken from one graph and a component from another have never been checked against each other, so accepting over an existing graph is refused outright unless asked for explicitly, and even then the old graph is moved aside rather than destroyed, because replacing is a decision about which graph governs and not a decision to lose work. And it reports the number nothing else can supply: how many places in the code that is already here the new rules refuse today. A mined rule earns its status from how the code is usually written, never from a check that the repository is clean, so a perfectly well-formed graph can refuse hundreds of existing files the moment it is switched on. Somebody accepting one is entitled to know that before they do, not after.

It also runs before a graph exists, which makes it the second command that cannot open one first. That is why every refusal it can reach beforehand is its own rather than the shared missing-graph message, and why the rule describing the command layer had to stop saying that the initializer was the only such command.
