## [2026-07-11T03:28:01.669Z]
New command that re-runs a rule against its own library of pass/fail example files so a maintainer can confirm the rule still behaves as intended — for free when the rule is checkable locally, or through the real reviewer for judgment-based rules, printing the reviewer-call budget before the first call. It never touches saved verdicts; it only writes a local, gitignored results log plus, for reviewer-based cases, one telemetry line each. Failure output deliberately shows only the example label, content hashes, and pass/fail — never the example source — because this is a regression fixture for sharpening a rule, not a sensitivity or specificity measurement, and the committed example set is already visible to the author by definition. Exit is 1 on any MISS or FALSE-ALARM, 2 when some example could not be evaluated, and 0 when clean.

## [2026-09-06T22:02:09.419Z]
The corpus gained a way in. Code that got past a rule is the strongest case that rule can hold, and the moment worth capturing it is the moment somebody finds it, so the whole act is one step: read the file as it stood at a named commit, file it under the corpus convention with its origin in the name, measure the rule against it, and record what happened in the rule's own log. A rule that does not catch its own escape is reported as exactly that, with a non-zero exit, and the case is KEPT. That is deliberate and it is the point: a corpus that only ever accepts cases a rule already passes can never tell anybody anything, so the case sits there failing until the rule is sharpened enough to catch it. Nothing is written when the commit is not in the repository, the file was not there at that commit, the file is empty, the same bytes are already a case, or the rule only bundles others; and a case that turns out to be unmeasurable is taken back out, because a fixture nobody can measure is worse than none. The new case is measured through the same wiring the whole corpus is measured through — one reviewer tier, one prompt limit, one graph-access trap, one set of sidecar and telemetry lines — so a case added from history is judged under exactly the conditions everything else is judged under. A second wiring would eventually disagree with the first and nobody could say which run to believe. Naming the rule stopped being enforced by the argument parser and is checked in the command itself, because a required flag on a command that carries subcommands is demanded before a subcommand is ever reached — which would have made the new form refuse the very flag it was given.
