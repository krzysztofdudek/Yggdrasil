## [2026-07-24T12:09:07.921Z]
Agents previously had no dedicated way to fetch the full, current operating manual for this kind of tool: it only existed as a file generated once and copied into a repository, so it could go stale the moment the tool itself was upgraded without a fresh setup run, and one integration silently cut the content off partway through with no warning to anyone. This command exists so an agent can always pull the manual live from whichever version of the tool is actually installed, guaranteeing the content and the installed tool can never drift apart. A digest-only mode prints just the small anchored summary block, so the same canonical text that gets embedded in a repository can later be checked for staleness by comparing hashes, without duplicating the reasoning behind it in two places.
## [2026-09-10T17:16:58.712Z]
The operating manual is the same in every repository, which is right for a manual and wrong for one fact: whether the repository the agent is standing in publishes rules for other people to install, or runs rules installed from somewhere else. Both change what an edit under a package directory means — in the first the agent is writing law that will be copied verbatim into other repositories, and in the second it is looking at a copy that must not be edited at all — and an agent that does not know which it is in will find out by being refused. The manual now gains one sentence, pointing at the topic that explains it, when the repository's own files say it is one or the other, and nothing at all otherwise. The probe sits in the command because that is the layer permitted to look at the disk; the sentence is built by the knowledge document that owns the subject, which is handed the answer rather than going looking for it. Nothing is added to the manual's own text, which is written by hand and stays that way.
