## [2026-09-10T17:16:34.576Z]
Until now a repository could install rules published elsewhere but there was no supported way to publish any: an author had to work out the shape of both manifests from the consuming side and had nothing to run before pushing a tag that other people would install from. This command is the publishing side. Starting a marketplace writes the manifest that is the whole record of what the repository publishes, and refuses rather than overwrite one that is already there, because rewriting it would silently drop every package named in it and nothing else in the repository would notice. When the repository already keeps GitHub workflows it adds one of its own that runs the check on every push, and leaves an existing one alone rather than refusing, because a workflow already correct is the state the command wanted and failing over it would leave a half-made marketplace behind. It writes a dedicated workflow file rather than appending a step into somebody else's, deliberately: appending means editing a document whose job names, matrix and indentation have to be inferred, and getting that wrong breaks their build rather than this one. The constraint both halves rest on is that a marketplace is not a Yggdrasil project. It publishes law rather than enforcing any, so it normally carries no graph at all, and a command that loaded one would refuse every real marketplace and send its author to build the wrong thing. The repository is located by walking up for the manifest, the way a repository is located by walking up for its own directory, so somebody standing in a package means the repository they are standing in; where there is no manifest anywhere above, the refusal names the directory they are actually in rather than a root they never mentioned.

The CLI now speaks one output grammar: every finding is a block headed error[label] or warning[label] with lowercase labelled at:, why: and fix: fields, every command error is error[code]: what with a labelled why and a next: step, and a report ends with one next: step and optionally a then: step. This command's remaining capitalised Next: or Warning: lines are lowercase, its counts agree with their nouns, and its first-level text says reviewer rule where it said LLM aspect.
