## [2026-07-13T18:13:55.436Z]
Introduces the incident ledger command. The tower had instruments that all reason about the graph from the inside; it had no way to record what actually got through. This command lets a human write down a real escape — a concern that shipped uncovered, a rule that judged the wrong thing, a reviewer that could not see what mattered, a lone judge that missed what a panel would have caught, or a miss that was not about enforcement at all — with the cause named as a mandatory tag and the story of how it surfaced as a mandatory reason. Recording an incident is human-signature territory, the same authorization class as a waiver: the tag vocabulary is closed and validated, an unknown cause is refused with the valid list and nothing is written, and the command never invents an entry. It only ever appends one timestamped block to the committed ledger; it touches no verdict and no lock.
## [2026-07-14T08:47:46.312Z]
When listing recorded incidents, the cause tag shown for each entry is taken verbatim from the committed ledger, which a person can edit by hand. A hand-edited or merge-mangled header could place raw control characters inside that tag, and printing them unchanged to a terminal risks smuggling escape sequences onto the reader's screen. The listing path now renders the tag as inert inline text — control characters folded to spaces and surrounding whitespace collapsed — so what reaches the terminal is always plain, legible text. The recording path is unchanged: adding a new incident still validates its cause against the closed set of sanctioned causes.
## [2026-07-14T09:37:40.273Z]
Added optional per-rule attribution to incident recording: a maintainer may name the specific rule an escape slipped past when the cause is a miscalibrated rule. The named rule is validated against the graph's known rules and rejected with guidance if it does not exist, so a recorded miss can never be tied to a rule that is not real. Attribution is optional; omitting it preserves the prior behaviour of recording an unattributed incident. The motivation is to let a recorded miscalibration point at the rule responsible, so the rule's own health can later reflect how often it has been blamed for a real miss.
## [2026-09-23T22:03:09.321Z]
Command errors now go through the shared CLI output layer (fail, or failAndExit where the command exits at once) instead of each command writing its own red Error: what/why/next line to stderr, and the commands that kept a private failWith or emitError copy of that line now use the shared one. The words a reader sees are unchanged. One place now owns how a command error reads and where it goes, so wording and stream can change once for every command, and an invocation that answers in JSON can be given a machine-readable error instead of nothing on stdout.
## [2026-09-24T07:23:29.605Z]
The CLI now speaks one output grammar: every finding is a block headed error[label] or warning[label] with lowercase labelled at:, why: and fix: fields, every command error is error[code]: what with a labelled why and a next: step, and a report ends with one next: step and optionally a then: step. Scripts that parsed the old capitalised Why:, Fix: and Next: lines are sent to the JSON documents, which carry the same facts. This command's remaining capitalised Next: or Warning: lines are lowercase, its counts agree with their nouns, and its first-level text says reviewer rule where it said LLM aspect.
## [2026-09-24T13:50:58.734Z]
Every byte this command prints now goes through the output layer: stdout and stderr through writeOut and writeErr, colour through paint, instead of process.stdout.write, process.stderr.write and a chalk import of its own. The repository now refuses a direct stream write, a console call or a chalk import outside that layer, so that where output goes, what guards it and when it is decorated are decided in one place and cannot drift command by command again, as they had across hundreds of write sites before the layer existed.
## [2026-09-24T14:08:20.979Z]
The comment at the clock read says what the value is — the time the incident was recorded, an audit timestamp of the record like a log entry's date — and that the command is the boundary that reads the clock while the store keeps none, so the determinism of the store is not mistaken for a gap in it.
