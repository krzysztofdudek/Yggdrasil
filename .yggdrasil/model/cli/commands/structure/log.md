Introduces a read-only structural dashboard command that reports the shape of the architecture in three views: the dependencies that reach farthest across the hierarchy (each with how many tree levels it jumps and whether it crosses a declared contract), how component groups at each level of the tree depend on one another (group counts, cross-group dependency counts, and whether those dependencies flow one way or form a cycle), and how much of the system an average component can reach by following dependencies. The edge set it measures is the union of declared structural relations (calls/uses/extends/implements) and statically detected code dependencies, with event relations excluded; that definition is printed on every run so the numbers are unambiguous. It is deliberately an instrument, never a gate: it never reads or writes the verification lock and never calls a reviewer, and it exits successfully whenever the graph loads (including when verification is currently failing), failing only when there is no graph to load. It obtains the statically-detected dependency edges through the read-only portal engine facade rather than the dependency-resolution layer directly, because a command handler is architecturally not permitted to depend on that resolution layer; the pure ranking math lives in a separate metrics core kept walled off from the code that decides exit codes, so a diagnostic ranking can never influence whether a build passes.

## [2026-07-11T20:59:43.144Z]
Exposed the read-only structural dashboard's edge-universe computation as a plain-data accessor so an out-of-band, offline structural report can reuse the EXACT same universe the dashboard reports, rather than re-deriving the dependency graph through a second reader that could silently drift.

The structural edge universe here is a specific, load-bearing definition: the union of declared structural relations (calls, uses, extends, implements) with statically detected cross-node code dependencies, excluding event relations (emits, listens). Any independent re-derivation risks diverging on subtle points (which relation types count, how detected edges are unioned and deduped, lineage handling), and a divergent reader would make an external report quietly disagree with what the dashboard shows. Concentrating the computation in one accessor that both the dashboard rendering and the external report call keeps them provably identical.

The accessor is read-only by construction: it loads the graph and runs the relation pass (parse plus resolve) with no verdict written and no lock touched, and it is not a command handler — graph-load failure is delegated to the shared load-or-abort helper exactly as the command does. It changes none of the dashboard's rendering logic or output.
