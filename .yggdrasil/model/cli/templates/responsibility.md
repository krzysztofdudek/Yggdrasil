# Templates Responsibility

Default templates and platform rules — used by `yg init`.

**In scope:**

- **default-config.ts:** `DEFAULT_CONFIG` — YAML string for default yg-config.yaml. Node types as object keyed by type name (module, service, library, infrastructure), each with a description string. Three artifacts: responsibility.md (always required, included_in_relations), interface.md (required when has_incoming_relations, included_in_relations), internals.md (never required). Quality thresholds for min_artifact_length, max_direct_relations, context_budget. Also exports `DEFAULT_ARCHITECTURE` — YAML string for default yg-architecture.yaml with node types, descriptions, optional aspects/relations per type.
- **platform.ts:** `installRulesForPlatform(projectRoot, platform)` — writes rules to platform-specific path; `PLATFORMS`, `Platform` type. Unknown platform falls through to generic.
- **rules.ts:** `AGENT_RULES_CONTENT` — canonical agent rules (operating manual); hand-tuned, do not generate programmatically. Used by platform.ts. Split internally into three cognitive sections (`CORE_PROTOCOL`, `OPERATIONS`, `KNOWLEDGE_BASE`) optimized for LLM attention patterns, concatenated into a single export. Core Protocol covers dual triggers in `critical_protocol` (task-level: `yg select --task` before any brainstorming/design/planning/implementation; file-level: `yg context --file` before any source file interaction), quick start protocol reinforcing both triggers with "follow CLI guidance" framing (CLI messages follow WHAT→WHY→NEXT structure; suggestedNext gives concrete step + remaining scale), and two graph-first paths (understand via `yg context`, assess impact via `yg impact`), five core rules (Rule 2: "The graph is the specification; code implements it" — knowledge absorption, self-sufficiency, per-file timing, planning integration; plus "capture why NOT" with rejected alternatives), failure states, escape hatch, environment check, and subagent delegation (requires subagents to read .yggdrasil/agent-rules.md as first instruction + explicit deliverables: code, graph nodes, `yg check` passing). Operations covers conversation lifecycle (using `yg check`), modify code/graph checklists (step 6 references "follow CLI's suggested next command"), greenfield graph-first workflow, bootstrap mode, and error recovery. Knowledge Base covers graph structure, artifact structure, context assembly, information routing, creating aspects/flows, operational rules with completeness test, CLI commands section (compact list, not tables), error categories section (replaces detailed error code tables with category summaries: Drift E020-E021, Structural E001-E013, Coverage E022, Completeness E030-E039, Architecture E050-E058, Semantic E055-E056), approve enforcement (prose matrix replacing table: both sides changed→ACCEPTS, one side changed→REFUSES, only upstream changed→REFUSES; conscious exception described in prose), and quick routing table.
- **graph-schemas/:** yg-node.yaml, yg-aspect.yaml, yg-flow.yaml, yg-architecture.yaml — schemas for each graph layer, copied to .yggdrasil/schemas/ during init

**Out of scope:**

- Templates in .yggdrasil/schemas/ (generated by init, not part of source)
