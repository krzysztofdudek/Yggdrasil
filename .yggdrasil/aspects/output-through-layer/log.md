## [2026-09-24T13:38:15.883Z]
Added by the owner's mandate that the new CLI communication system be impossible to regress. The output layer now owns the words, layout, counts, colour and streams of everything the CLI prints, but nothing stopped the next module from writing to a stream directly, importing chalk, or spelling a plural by hand, which is exactly how the audit found hundreds of write sites and one fact reading differently per command. The rule is directory-scoped over the whole shipped source tree so a module written tomorrow is covered on its first day. It exempts the layer itself and utils/count.ts, and allows three named sinks exactly the stream write they need: the entry point's last-resort handlers, which run when the layer itself may have failed and may not depend on it; the debug tee, which wraps both streams to copy every byte into the debug log; and the drain before exit, which writes an empty chunk only to be called back. Its count check reads a substitution before a counted noun as a number, so it can flag a non-count substitution there; that is why it is labelled errs over.
## [2026-09-27T20:47:09.534Z]
The errs over label was only half the truth. A consistency audit found about a hundred hand-built counts in the shipped source that the check lets through: counts of nouns other than pairs, nodes and files, and nouns chosen by a whole-word conditional, including hand-built pair counts the description claimed to cover. The check also still over-flags a non-count substitution before files. Since it errs both ways, the label is dropped, as for the other mixed rule, and the description now names the forms it polices and the ones it does not, so a green is not read as every count going through count(). The rule and its reach are unchanged.
