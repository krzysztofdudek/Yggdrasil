Added when the command layer was found ending the process two ways side by side: 84 bare process.exit calls next to the shared helpers, 60 of them the inline write-the-error-then-exit pair that failAndExit already is. A bare exit ends the process at once, and when the output goes to a pipe whatever the reader has not yet taken is still queued inside the process and is dropped silently, exactly when the output is longest; measured on Linux, a report exiting that way through a slow reader arrived cut at 64 KiB. Once every exit went through failAndExit or exitAfterFlush, nothing stopped the next command from writing a bare exit again, so this rule refuses one anywhere under the command layer, a call or a bare reference alike. Four sites keep a raw exit because they are the mechanism or not the end of an answer — failAndExit itself, the backstop timer inside exitAfterFlush, the portal shutdown on Ctrl+C, and a cancelled interactive setup prompt — each listed in the rule with its reason and allowed exactly the one it has, so a second in the same file is still refused. It is labelled errs under because an exit reached through an alias is not seen.
